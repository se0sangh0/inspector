# 거두는 자 시안 인수·후처리 순서

- 작성일: 2026-09-13
- 범위: **스프라이트 제작만.** 엔진 매핑·게임 배치는 이후 단계이며 여기서 다루지 않는다
- 제작(이미지 생성): **Codex** — 출력은 `production-drafts/reaper/` (Codex 소유)
- 후처리·검수: **Claude** — 기존 `tools/` 5종만 사용하고 도구를 늘리지 않는다
- **이미지가 도착하기 전에는 이 문서의 어떤 단계도 실행하지 않는다**
- **[갱신 2026-09-13]** `idle_float` RGBA v2 가 도착했다. 진행 기록은 §8 에 있다

## 1. 작업용 규격 — 승인이 아니다

기존 6종 12시트와 나란히 비교하기 위해 **셀 384×512** 를 **작업용 시안 규격**으로
쓴다. 사용자 최종 규격 승인이 아니다. 256×256 대 384×512 미결은
[`README.md`](README.md) §4 에 그대로 남아 있다.

| 항목 | 작업용 값 | 근거 |
|---|---|---|
| 셀 | 384×512 | 기존 12시트와 동일해 도구·미리보기를 그대로 쓴다 |
| idle_float 프레임 | 8 | 기존 파이프라인과 같은 길이 |
| 격자 | 4열 × 2행 | 시트로 받을 경우 |
| 배경 | **실제 알파 투명** | 격자무늬를 그림에 구워 넣지 않는다 |

## 2. Codex 에게 필요한 입력 형태

둘 중 **하나**면 된다. 섞어서 주지 않는다.

### A안 — 개별 프레임 (권장)

```
production-drafts/reaper/<모션명>/01.png … 08.png
```

- 파일명은 **빈칸 없는 1..N 연번**. `build_sheet.py` 가 빠진 번호를 거부한다
- 전부 같은 크기. 크기가 다르면 조립이 중단된다(재표본화하지 않는다)
- RGBA, 실제 알파

### B안 — 시트 한 장

```
production-drafts/reaper/<모션명>_384x512x8.png   (1536×1024, 4열×2행)
```

- 시트로 오면 내가 먼저 8칸으로 쪼갠 뒤 A안과 같은 흐름을 탄다
- 쪼개기는 **새 도구를 만들지 않고** 그때 한 번 쓰는 스크립트로 처리한다
  (고블린 왕복 시험에서 쓴 것과 같은 방식)

### 앵커는 별도

앵커는 모션이 아니라 **단독 참조 1장**이다. 프레임 규격을 따르지 않아도 된다.
`production-drafts/reaper/anchor/` 아래에 두면 대조에만 쓴다.

## 3. 후처리 순서 — 기존 도구만

| # | 단계 | 도구 | 확인할 것 |
|---|---|---|---|
| 1 | 알파·크기 1차 확인 | (즉석 Pillow 한 줄) | RGBA 인가, 격자가 구워지지 않았나, 8장 다 같은 크기인가 |
| 2 | 시트·JSON 조립 | `build_sheet.py --cell 384x512 --cols 4 --loop` | 셀 불일치·번호 누락이면 여기서 멈춘다 |
| 3 | 기술 검수 | `verify_sheet.py` | 알파 실재, 셀 기하, 빈 프레임, 해시, 프레임↔시트 일치 |
| 4 | 프레임 계측 | `frame_metrics.py --loop` | 몸통 흔들림, 크기 점프, 빈 프레임, **루프 경계** |
| 5 | 콘택트 시트 | `contact_sheet.py --pivot-x <값>` | 눈으로 볼 판 |
| 6 | 시각 검수 | (사람이 본다) | §4 항목 |
| 7 | 미리보기 등록 | `make_preview_manifest.py` | 기존 판정·pending 보존됨 |

**2번에서 실패하면 3번 이후로 넘어가지 않는다.** 도구가 재표본화를 거부하므로
크기 불일치는 시안을 다시 받아야 하는 신호다.

## 4. 거두는 자 전용 시각 검수 항목

현행 기준이 유지되는지 본다. 근거는
[`../source_reference/measurements.json`](../source_reference/measurements.json)
의 `currentProductionBaseline` 이다.

**낫날 방향은 2026-09-13 사용자 지시가 키아트 기록보다 우선한다.**
기준 시안은 `production-drafts/reaper/reaper_anchor_v2_blade_left_raw.png` 다.

| 항목 | 기준 |
|---|---|
| 두건 속 | **완전한 검정 공백.** 이목구비·눈빛이 생기면 안 된다 |
| 짚·잔가지 깃 | 방사형으로 뻗고 **캐릭터 왼쪽이 더 크다** |
| 로브 | 겹겹의 넝마, 밧줄·구슬 허리끈 |
| 낫 | 장대 위쪽 큰 곡선 날. **날이 화면 왼쪽·캐릭터 바깥으로 뻗고 끝도 왼쪽을 향한다** (2026-09-13 사용자 지시) |
| 낫 쥔 손 | **캐릭터 오른손(화면 왼쪽).** 프레임 사이에서 손이 바뀌면 안 된다 |
| 빈손 | **캐릭터 왼손(화면 오른쪽).** 깃 아래에서 나온 앙상한 손가락. **v2 새 시안에 표현됨 · 전체 디자인 최종 승인 전** (사용자가 명시한 변경은 낫날 방향뿐) |
| 손–장대 접점 | 자루 위에서 미끄러지지 않는다 |
| 비대칭 | 낫 팔이 깨는 좌우 비대칭을 대칭화하지 않는다 |
| 부유 | **발이 없다.** 바닥 접지·그림자를 그리지 않는다 |

## 5. 부유 캐릭터의 정렬 — 기존 6종과 다른 점

기존 6종은 **발 기준선 y=500** 으로 정렬한다. 거두는 자는 발이 없어 그 기준을
쓸 수 없다.

- 정렬 기준은 **몸통 중심(허리끈 높이)** 을 쓴다
- `idle_float` 의 상하 부유는 **의도된 이동**이다.
  `frame_metrics.py` 가 중심 이동을 플래그해도 그것만으로 결함이 아니다.
  **좌우(centre X) 흔들림과 세로(centre Y) 부유를 나눠 읽는다**
- 낫 날이 위쪽으로 나가므로 **불투명 영역 기준 자동 크롭·자동 정렬을 쓰지 않는다**
- `contact_sheet.py --pivot-x` 는 세로선만 그린다. 좌우 기준 확인용이며
  세로 부유 확인에는 쓰지 않는다

## 6. 기존 6종 12시트 취급

**정본은 손대지 않는다.** `normalized_v1/` 아래 시트 12·프레임 96은 읽기 전용이다.

수정 후보가 필요하면 정본을 덮어쓰지 않고 **버전별 사본**으로만 만든다.
사본에는 형식과 사유를 파일명·기록에 남긴다. 예:
`defender_attack_8f_v2_타격통합.png` + 왜 만들었는지 한 줄.

**일괄 재생성하지 않는다.** 현재 열려 있는 판정은 defender 가독성 1건뿐이고
(§5-C), 나머지 11종은 통과 후보다.

## 7. 이 문서가 뜻하지 않는 것

- 384×512 가 **최종 규격으로 승인됐다는 뜻이 아니다**
- 시안이 도착했다는 뜻이 **아니다.** 작성 시점에 `production-drafts/reaper/` 는
  아직 없었다. 이후 도착분은 §8 에 적는다
- 어떤 이미지도 검수를 통과했다는 뜻이 **아니다**

## 8. 진행 기록 — `idle_float` RGBA v2 (2026-09-13)

입력은 `production-drafts/reaper/rgba_v2/` 다. Codex 소유이며 **읽기만 했다.**
원본은 흰 배경 8포즈 `reaper_idle_float_8f_v1_raw.png` 다.
§2 의 A안·B안과 달리 Codex 가 프레임·시트·JSON 을 함께 만들었다.

| # | 단계 | 한 사람·도구 | 결과 |
|---|---|---|---|
| 1 | 알파·크기 1차 확인 | Claude 즉석 스크립트 | RGBA 384×512 8장, 알파 0·255 만, 셀 경계 닿음 0, 고유 8/8 |
| 2 | 시트·JSON 조립 | Codex (`normalize_sheets.extract` 재사용, 공통 배율 0.8523) | `build_sheet.py` 는 쓰지 않았다. 결과는 3단계로 확인했다 |
| 3 | 기술 검수 | `verify_sheet.py` — Codex 실행, Claude 재실행 | 10 통과 · 0 실패. 양쪽 결과가 같다 |
| 4 | 프레임 계측 | `frame_metrics.py --loop` — Claude | 중심 X 폭 3.0px, 중심 Y 폭 9.0px, 플래그 0 |
| 5 | 콘택트 시트 | `contact_sheet.py --pivot-x 192` — Claude | `contact-sheets/reaper_idle_float_8f_v2.png` |
| 6 | 시각 검수 | Claude (보드 10장, 미리보기 한 칸씩) | **동작 검수 중 · 수정 후보 2건** → [`REAPER_IDLE_REVIEW.md`](REAPER_IDLE_REVIEW.md) |
| 7 | 미리보기 등록 | **manifest 직접 수정** (도구 미사용) | 재생 13 + 미등록 3. 상태 `검토 시안/동작 검수 중` |

**7단계에서 `make_preview_manifest.py` 를 쓰지 않은 이유.**
이 도구는 폴더 하나만 읽어 목록을 새로 만든다.
`rgba_v2` 폴더로 돌리면 기존 12종이 목록에서 빠진다.
`normalized_v1` 폴더로 다시 돌리면 거두는 자 항목이 빠지고 경고만 남는다.
그래서 한 항목만 손으로 넣었다. **목록을 다시 생성하면 이 항목을 다시 넣어야 한다.**

**[갱신 2026-09-14]** 미리보기 항목은 `rgba_v4_scythe` 시트로 교체됐다. 상태는 `보정 시안/동작 재검수` 다.
경과는 [`REAPER_IDLE_REVIEW.md`](REAPER_IDLE_REVIEW.md) §8·§9.

§4 기준 항목별 결과와 수정 범위는 [`REAPER_IDLE_REVIEW.md`](REAPER_IDLE_REVIEW.md) §3·§4 에 있다.
