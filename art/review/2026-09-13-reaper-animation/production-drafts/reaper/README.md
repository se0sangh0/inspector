# 거두는 자 제작 시안

- 현재 선택 후보: `rgba_v4_scythe/reaper_idle_float_8f_v4.png`
- 상태: **낫 부분 보정 8프레임 기술 검수 통과 시안. 독립 동작 검수 중, 최종 승인 전.**
- 게임 코드·배치·Assets·Unity 설정에는 반영하지 않았다.

최신 보정 근거와 전후 비교는 [`rgba_v4_scythe/README.md`](rgba_v4_scythe/README.md)를 본다.
아래는 원화 생성과 v2 후처리까지의 제작 이력이다.

## 기준과 제작

원화는 내장 image_gen으로 생성했다. 사용자의 낫 방향 수정에 따라
`reaper_anchor_v2_blade_left_raw.png`를 기준으로 삼았다.
자루는 캐릭터 오른손(화면 왼쪽), 낫날 끝은 화면 왼쪽 바깥을 향한다.
원화 파일은 RGB이며 격자 배경이 포함된 검토 시안으로 보존한다.
낫 방향 지시는 반영했지만 캐릭터 전체의 최종 승인을 의미하지 않는다.

`reaper_idle_float_8f_v1_raw.png`는 흰 배경의 새 8프레임 원본이다.
`idle-float-8f-v1-prompt.txt`에 사용한 생성 프롬프트를 저장했다.
사용자가 기존 후처리 도구로 투명 PNG 변환을 명시적으로 승인했다.

## 후처리

기존 `2026-09-10-animation-8f/normalize_sheets.py`의 `extract`를 재사용했다.
그 도구의 전체 배치 작업은 실행하지 않아 기존 12종 정본은 보존했다.
부유 동작을 지우지 않도록 발 기준선 정렬 대신 원래 셀 내부 위치를 유지하고,
전 프레임에 동일한 약 0.8523 배율과 동일한 이동을 적용했다.
리샘플링은 nearest-neighbour이며 새 픽셀 그림을 덧그리지 않았다.

첫 RGBA 버전은 팔·자루 사이에 흰 배경 조각이 남아 있었다.
어두운 배경에서 확인한 뒤 v2에서 밝은 무채색 배경 성분만 추가 제거했다.
방법과 프레임별 제거량·해시는 `rgba_v2/processing.json`에 기록했다.

## v2 당시 산출물과 확인

- 투명 PNG: `rgba_v2/frames/01.png`부터 `08.png`까지 8장, 각 384×512.
- 시트: `rgba_v2/reaper_idle_float_8f_v2.png`, 1536×1024, 4열×2행.
- 메타데이터: 동일 이름 JSON. 프레임당 200ms, 합계 1600ms, 반복.
- GIF: `rgba_v2/reaper_idle_float_preview.gif`. 어두운 배경을 합성한 관찰용 파일.
- 미리보기: `rgba_v2/preview/index.html`. 기존 미리보기 코드를 복사해 사용했다.
- 실제 RGBA 알파 0/255, 8프레임 전부 서로 다름, 셀 경계 접촉 없음.
- 기존 build_sheet/verify_sheet 검사 10개 통과, 실패·건너뜀 0개.
- 별도로 RGBA 배열을 비교해 8개 시트 영역이 개별 프레임과 완전히 같음을 확인했다.
- 어두운 배경의 정지 비교와 HTTP 브라우저에서 프레임 진행을 확인했다.

384×512는 비교용 시안 규격이며 사용자 최종 규격 승인으로 기록하지 않는다.
미리보기 기준점 192,256은 셀 중앙 폴백이며 실측 몸통 피벗이나 엔진 설정이 아니다.
루프 경계·무기 길이/파지·의복의 연속성과 자연스러움은 추가 시각 검수 대상이다.
양손 공격·한손 공격·가리키기 모션은 아직 제작하지 않았다.
