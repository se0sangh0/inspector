## 3. 구현 항목 8가지

### REQ-LAND-001 — 언어 선택 우선순위와 저장

**현재 상태**

- `index.html:2058`이 `updateCopy("zh")`로 언어를 고정 호출한다.
- 저장 기능이 없다. `localStorage` 키가 0개다.
- 언어 전환 함수는 `index.html:1973`의 `updateCopy(language)`다.
  이 함수는 `root`의 `lang` 속성과 `document.documentElement.lang`을 함께 바꾼다.
- 각 언어의 `lang` 값은 `zh-Hant`(1554행), `en`(1639행), `ko`(1724행)이다.
- 선택기는 `index.html:1305`의 `#inspector-language-select`다.
  값은 `zh` / `en` / `ko` 순서로 들어 있다.

**바꿀 내용**

`updateCopy("zh")` 고정 호출을 다음 우선순위로 바꾼다.

1. `localStorage`에 저장한 사용자 선택값
2. `navigator.languages`로 판별한 값
3. 번체중국어(`zh`) 기본값

**판별 규칙**

`navigator.languages` 배열을 앞에서부터 훑는다. 처음 맞는 항목에서 멈춘다.

| 태그 조건 (대소문자 무시) | 결과 |
| --- | --- |
| `zh-TW`, `zh-Hant`, `zh-HK`로 시작 | `zh` |
| `ko`로 시작 | `ko` |
| `en`으로 시작 | `en` |
| 위 어디에도 맞지 않음 | 다음 항목으로 넘어간다 |
| 배열 전체에 맞는 항목이 없음 | `zh` |

`zh-CN`, `zh-Hans` 같은 간체 태그는 위 표에 없다. 그래서 건너뛴다.
배열에 다른 후보가 없으면 최종 결과는 `zh`가 된다.

`navigator.languages`가 없는 환경에서는 `navigator.language` 하나만 같은 규칙으로 본다.
둘 다 없으면 `zh`를 쓴다.

**저장 규칙**

- 저장 키 이름은 `inspector-landing-language`로 한다.
- 저장 값은 `zh` / `en` / `ko` 중 하나다. 다른 값이 읽히면 무시하고 2단계로 넘어간다.
- 선택기의 `change` 이벤트에서 선택한 값을 저장한다.
- 저장 목적은 전시 부스 시나리오다. 부스 기기의 운영체제가 한국어 로캘이어도,
  운영자가 한 번 번체중국어로 바꾸면 그 값이 계속 유지돼야 한다.

**예외 처리 (ERR-LAND-001)**

- `localStorage` 읽기와 쓰기를 각각 `try` / `catch`로 감싼다.
- 사생활 보호 모드에서는 `localStorage` 접근이 예외를 던진다.
- 예외가 나면 조용히 무시한다. 콘솔에 오류를 남기지 않는다.
- 읽기가 실패하면 2단계(브라우저 로캘)로 넘어간다.
- 쓰기가 실패해도 화면의 언어 전환은 정상으로 끝나야 한다.

**깜빡임 금지 규칙 (REQ-LAND-001-A)**

- 정적 HTML 기본값을 그대로 둔다. `<html lang="zh-Hant">`와 마크업 안의
  번체중국어 문구를 바꾸지 않는다.
- 스크립트는 지금처럼 `</body>` 직전에서 동기로 실행된다.
  첫 페인트 전에 문구 교체가 끝나야 한다.
- 초기 언어 적용에는 `select`의 `change` 핸들러에 있는
  `inspector-changing` 클래스와 `setTimeout` 90ms 지연을 **쓰지 않는다**.
  이 지연은 사용자가 직접 선택기를 바꿀 때만 쓴다.
- 초기 언어를 적용할 때 `select.value`도 같은 값으로 맞춘다.
  그래야 선택기 표시와 화면 언어가 어긋나지 않는다.

### REQ-LAND-002 — 한글·번체중국어 라벨 자간 정리

**현재 상태**

제목(`h1` / `h2`)은 이미 처리했다. `index.html:67-71`에 다음 규칙이 있다.

```
#inspector-expo-mockup:lang(ko),
#inspector-expo-mockup:lang(zh-Hant) {
  --inspector-title-tracking: 0;
  --inspector-title-leading: 1.26;
}
```

문제는 작은 라벨이다. 이 라벨들은 위 변수를 쓰지 않고 영문용 자간을 직접 적었다.

| 선택자 | 줄 번호 | 현재 자간 | 글자 크기 | 실측 자간 |
| --- | --- | --- | --- | --- |
| `.inspector-hero-eyebrow` | 174 | `0.2em` | 13px | 2.6px |
| `.inspector-kicker` | 1054 | `0.14em` | 13px | 1.82px |
| `.inspector-hero-meta dt` | 248 | `0.14em` | 12px | 1.68px |
| `.inspector-ledger-row strong` | 995 | `0.14em` | 12px | 1.68px |

**바꿀 내용**

1. 라벨 전용 자간 변수를 새로 만든다. 이름은 `--inspector-label-tracking`으로 한다.
2. 기본값은 지금 값과 같게 둔다. `.inspector-hero-eyebrow`만 값이 다르므로
   변수를 두 개로 나눈다.
   - `--inspector-label-tracking`: 기본 `0.14em`
   - `--inspector-label-tracking-wide`: 기본 `0.2em`
3. 위 표의 4개 선택자에서 하드코딩한 자간을 해당 변수로 바꾼다.
   - `.inspector-hero-eyebrow` → `--inspector-label-tracking-wide`
   - 나머지 3개 → `--inspector-label-tracking`
4. `#inspector-expo-mockup:lang(ko), #inspector-expo-mockup:lang(zh-Hant)` 규칙
   안에서 두 변수를 `0.01em`으로 낮춘다. 허용 범위는 `0` ~ `0.02em`이다.

**지켜야 할 조건**

- **영어일 때는 현재 값을 그대로 둔다.** 영문 스몰캡 라벨의 의도한 디자인이다.
- `.inspector-flow-index`(줄 420)는 건드리지 않는다. `01` 같은 숫자만 표시한다.
  세 언어 모두 현재 `0.2em`을 유지한다.
- `index.html:1272-1273`의 좁은 화면 규칙에서 같은 선택자의 `line-height`를
  `1.6`으로 낮춘다. 이 규칙을 깨지 않는다.

### REQ-LAND-003 — `Noto Sans TC`를 Google Fonts CDN으로 연결 (C안)

> **결정 반영**: 사용자가 `NEEDS_MAIN_APPROVAL-A`에서 **C안(Google Fonts CDN 링크)**
> 을 골랐다. 자체 호스팅과 글자 단위 조각 만들기는 범위에서 뺀다.

**현재 상태**

- CSS는 `Noto Sans TC` / `Noto Sans KR` / `PingFang TC` / `Apple SD Gothic Neo`를
  선언한다(줄 53, 54, 60).
- 그런데 실제로 받아오는 웹폰트는 Space Grotesk와 JetBrains Mono 둘뿐이다.
  `<link>` 1개(줄 20)로 Google Fonts에서 받는다.
- 선언한 CJK 4종 중 확인한 브라우저에서 쓸 수 있던 것은 `PingFang TC` 하나였다.
  즉 Windows 부스 기기에서는 CJK 폰트가 시스템 기본값으로 떨어진다.
- 현재 `<link>` URL은 이렇다.
  ```
  https://fonts.googleapis.com/css2?family=Space+Grotesk:wght@500;700&family=JetBrains+Mono:wght@400;500;600&display=swap
  ```

**바꿀 내용**

`index.html:20`의 `<link>` **한 개**에 `Noto Sans TC`를 더한다. 새 `<link>`를
따로 만들지 않는다. 요청 수를 1개로 유지한다.

바꾼 뒤 URL은 이렇다.

```
https://fonts.googleapis.com/css2?family=Space+Grotesk:wght@500;700&family=JetBrains+Mono:wght@400;500;600&family=Noto+Sans+TC:wght@400;500;700&display=swap
```

- 이 URL은 실제로 확인했다. `HTTP 200`을 준다.
- `&display=swap`이 이미 붙어 있다. 그대로 둔다.
- 줄 18·19의 `preconnect` 2줄은 그대로 둔다. `fonts.gstatic.com` 연결이
  더 중요해졌으므로 오히려 도움이 된다.
- CSS 폰트 스택(줄 53·54·60)에서 `Noto Sans TC`가 CJK 1순위인 현재 순서를
  그대로 둔다. 이제 실제로 내려받으므로 선언과 동작이 일치하게 된다.

**굵기 검토 결과 — 400·500·700 세 개를 모두 요청한다**

굵기를 줄일 수 있는지 실제로 확인했다. **줄일 수 없고, 줄여도 얻는 것이 없다.**

근거 1 — 굵기 500은 한자를 담은 요소에서 실제로 쓰인다.

| 선택자 | 굵기 | 담고 있는 한자 문구 |
| --- | --- | --- |
| `.inspector-cta` | 500 | `查看玩法` (주 행동 버튼) |
| `.inspector-hero-eyebrow` | 500 | `怪異探查局` (브랜드 표시) |
| `.inspector-kicker` | 500 | `01 · 出牌流程` 등 구간 머리말 5곳 |
| `.inspector-ledger-row strong` | 500 | `類型`, `狀態` |
| `.inspector-action-strip h3` | 500 | 행동 예시 제목 |
| `.inspector-flow-index` | 500 | `01` (숫자만. 한자 없음) |

500을 빼면 위 5곳의 한자 두께가 400이나 700으로 바뀐다.
"굵기를 빼서 화면에서 글자 두께가 달라지면 안 된다"는 조건에 어긋난다.

근거 2 — 굵기를 빼도 전송량이 **0바이트**도 줄지 않는다.

Google Fonts는 굵기를 2개 이상 요청하면 Noto Sans TC를 **가변 폰트**로 준다.
실제로 확인한 결과는 이렇다.

| 요청 | 고유 파일 수 | 파일 주소 |
| --- | --- | --- |
| `wght@400;700` | 105개 | — |
| `wght@400;500;700` | 105개 | **위와 완전히 같음** |

`@font-face` 블록은 315개(105 × 3)로 늘지만 가리키는 파일은 105개로 같다.
브라우저는 조각마다 파일을 한 번만 받아 세 굵기에 모두 쓴다.
따라서 500을 넣는 비용은 없다.

**전송량 (Google Fonts에서 직접 측정한 값)**

| 항목 | 바꾸기 전 | 바꾼 뒤 |
| --- | --- | --- |
| 스타일시트 (렌더 차단) | 834 B (gzip) | 100,615 B (gzip) |
| Space Grotesk 라틴 조각 | 22,320 B | 22,320 B |
| JetBrains Mono 라틴 조각 | 31,340 B | 31,340 B |
| Noto Sans TC 조각 | 0 B | **1,303,624 B** |
| **폰트 파일 합계** | **53,660 B** | **1,357,284 B (약 1.29 MB)** |

- Noto Sans TC 조각은 전체 105개 중 **이 페이지의 한자 279자가 건드리는 20개**만
  내려온다. 전체 105개를 다 받으면 4,193,212 B다.
- 한국어와 영어로 바꿀 때 조각을 더 받는지는 미확정이다. 한글에는 `Noto Sans TC`
  글리프가 없다(8.1). 그래도 `unicode-range`는 걸려 있어서 브라우저가 조각을
  먼저 받아 볼 수 있다. QA-LAND-007-5에서 실측한다.
- 스타일시트 자체가 834 B에서 100,615 B로 늘어난다. 이 파일은 렌더를 막는다.
  전시장 네트워크가 느릴 때 첫 화면이 늦어질 수 있다.
- `font-display: swap` 덕분에 폰트를 받는 동안에도 글자는 바로 읽힌다.

## 5. 기술적 고려 사항

### 5.1. 단위 검사를 깨지 않는 방법 (가장 중요)

`site/tests/animation-player.test.cjs`는 `index.html`을 **문자열로 잘라서** 실행한다.
9번째 줄과 10번째 줄이 이렇다.

```
const html = fs.readFileSync(path.join(__dirname, '../preview/index.html'), 'utf8');
const source = html.slice(html.indexOf('      const spritePlayers ='), html.indexOf('      const formatCompanionText ='));
```

- 자르는 시작점은 `index.html:1816`의 `      const spritePlayers =`다.
- 자르는 끝점은 `index.html:1941`의 `      const formatCompanionText =`다.
- 두 문자열 모두 **공백 6칸 들여쓰기를 포함한 정확한 문자열**이다.

지켜야 할 규칙은 다음과 같다.

1. 두 줄의 들여쓰기, 변수 이름, `const` 키워드, 등호 앞뒤 공백을 바꾸지 않는다.
2. 두 선언의 앞뒤 순서를 바꾸지 않는다.
3. 잘라낸 구간(1816~1940행) 안에 새 코드를 넣지 않는다.
   그 구간은 `vm.runInNewContext`로 제한된 환경에서 돈다.
   그 환경에는 `localStorage`도 `navigator`도 없다. 넣으면 검사가 죽는다.
4. REQ-LAND-001의 언어 판별·저장 코드는 **잘라낸 구간 밖**에 둔다.
   권고 위치는 `const copy = {` 선언보다 위, 또는 `updateCopy` 정의 근처다.
5. 파일 어디에도 `      const spritePlayers =`와 같은 문자열이 한 번 더 나오면 안 된다.
   `indexOf`가 첫 번째 것을 찾기 때문이다.

### 5.2. 파일 구조

`index.html`은 CSS·HTML·JS를 한 파일에 인라인으로 담은 단일 파일이다.
이 구조를 그대로 지킨다. 파일을 나누지 않는다.

### 5.3. 외부 요청

C안을 골랐으므로 `fonts.googleapis.com`과 `fonts.gstatic.com` 요청은 **남는다.**
다만 `<link>` 개수는 1개를 유지한다. 두 번째 스타일시트 요청을 만들지 않는다.

### 5.4. 새로 만드는 파일

| 경로 | 내용 |
| --- | --- |
| `site/preview/assets/og-cover.webp` | 1200×630 공유 이미지 |
| `site/tools/build-og-cover.py` | 위 이미지를 다시 만드는 Pillow 스크립트 |

`site/tools/`가 없으면 새로 만든다. `site/preview/assets/fonts/`는 만들지 않는다.

### 5.5. 배포

- `main`의 `site/preview/**`가 바뀌면 GitHub Actions가 자동 배포한다.
- 워크플로는 `.github/workflows/deploy-pages.yml`이다.
- **Git push와 배포는 사용자가 따로 승인한 뒤에 한다.** 이 스펙은 로컬 구현까지다.
- `og:image`는 배포된 뒤에야 외부 미리보기에서 확인할 수 있다.
  배포 전에는 메타 태그 존재와 파일 크기만 확인한다.

#### QA-LAND-007 · Google Fonts CDN으로 연결한 `Noto Sans TC` (다시 씀)

C안을 골랐으므로 "네트워크를 끊어도 렌더링이 유지되는지"는 확인 대상이 아니다.
대신 아래 4가지를 확인한다.

**7-1. 폰트가 실제로 적용되는가**

> **주의: `document.fonts.check`로 판단하지 않는다.**
> 이 함수는 `unicode-range` 선언과 로드 상태만 본다. **조각 안에 그 글자의
> 글리프가 실제로 들어 있는지는 보지 않는다.** 그래서 폰트가 그리지 않는 글자에도
> `true`를 준다. 2026-09-12 실측에서 한글 5자가 모두 `true`를 줬지만 실제로는
> 폴백 글꼴이 그렸다. 8.1을 본다.
> 폰트 적용 확인은 **렌더링 결과**로만 한다. 아래 두 방법 중 하나를 쓴다.

- **Given** `<link>`에 `Noto Sans TC`를 더한 페이지를 번체중국어로 연다.
- **When (방법 1 · 권장)** 한자가 있는 요소(예: `h1`, `.inspector-cta`)를 고른다.
  개발자 도구의 Elements → Computed → **Rendered Fonts**를 본다.
- **When (방법 2 · 수치 비교)** 콘솔에서 canvas `measureText`로 폭을 비교한다.
  `document.fonts.ready`를 기다린 뒤 실행한다.
  ```
  const c = document.createElement('canvas').getContext('2d');
  const w = (ch, f) => { c.font = `16px ${f}`; return c.measureText(ch).width; };
  ['怪','異','查','看'].forEach(ch =>
    console.log(ch, w(ch, '"Noto Sans TC", monospace'), w(ch, 'monospace')));
  ```
  두 폭이 **다르면** `Noto Sans TC`가 그 글자를 그린 것이다. 같으면 폴백이다.
- **Then**
  1. 방법 1에서 표시되는 폰트 이름이 `Noto Sans TC`다.
     `PingFang TC`나 시스템 폰트가 아니다.
  2. 방법 2에서 한자 4자의 두 폭이 모두 다르다.
  3. 굵기 500 요소(`.inspector-cta`, `.inspector-kicker`)의 글자 두께가
     400·700 요소와 눈으로 구분된다.

**7-2. 실제 전송량을 기록한다**

- **Given** 개발자 도구 네트워크 탭을 열고 캐시를 끈다.
- **When** 페이지를 번체중국어로 새로 연다. 이어서 한국어와 영어로 바꿔 본다.
- **Then** 다음을 측정해 최종 보고에 적는다.
  1. `fonts.googleapis.com` 스타일시트의 전송 크기
  2. `fonts.gstatic.com`에서 받은 파일 개수와 합계 크기
  3. 언어를 바꾼 뒤 추가로 받은 파일 개수와 크기
  4. 예상값과 비교한다. 예상값은 아래와 같다.

| 항목 | 예상값 (미리 측정한 값) |
| --- | --- |
| 스타일시트 (gzip) | 약 100,615 B |
| Noto Sans TC 조각 | 20개 · 약 1,303,624 B |
| Space Grotesk 라틴 | 22,320 B |
| JetBrains Mono 라틴 | 31,340 B |
| 폰트 파일 합계 | 약 1,357,284 B |
| 한국어로 바꿀 때 추가 | **미확정. 7-5에서 실측한다** |

실측값이 예상값과 크게 다르면 원인을 적는다. 크게 다르다는 기준은 20% 차이다.

**7-3. 폰트가 바뀔 때 레이아웃이 밀리지 않는가 (FOUT)**

- **Given** `font-display: swap`을 쓴다. 폰트를 받기 전에는 대체 폰트로 그린다.
- **When** 개발자 도구에서 캐시를 끄고 네트워크를 `Slow 3G`로 낮춘다.
  가로 폭 **360px**에서 페이지를 새로 연다. 세 언어를 모두 본다.
- **Then**
  1. 대체 폰트에서 `Noto Sans TC`로 바뀌는 순간 가로 넘침이 생기지 않는다.
  2. 주 행동 버튼(`查看玩法`)의 글자가 버튼 밖으로 나가지 않는다.
  3. 푸터 3개 항목이 겹치지 않는다.
  4. 제목이 단어 중간에서 잘리지 않는다.
  5. Lighthouse의 CLS 값이 변경 전보다 나빠지지 않는다.

**7-4. 폰트 요청이 막혀도 페이지가 멀쩡한가**

- **Given** 개발자 도구의 네트워크 요청 차단에 `fonts.googleapis.com`과
  `fonts.gstatic.com`을 넣는다. 또는 호스트 파일로 막는다.
- **When** 페이지를 새로 열고 세 언어를 모두 본다.
- **Then**
  1. 페이지가 정상으로 뜬다. 빈 화면이 되지 않는다.
  2. 모든 글자가 시스템 폰트로 읽힌다.
  3. 가로 넘침과 버튼 겹침이 없다.
  4. 콘솔에 스크립트 오류가 0건이다. (폰트 요청 실패 기록은 예외로 인정한다.)

**7-5. 한국어로 바꿀 때 폰트 조각을 더 받는가 (실측만 한다)**

한글에는 `Noto Sans TC` 글리프가 없다(8.1을 본다). 그래도 `unicode-range`에는
한글 코드포인트가 선언돼 있다. 그래서 브라우저가 조각을 **먼저 받아 보고**
글리프가 없다는 것을 확인할 가능성이 있다. 그렇다면 순수한 낭비다.

- **Given** 개발자 도구 네트워크 탭을 열고 캐시를 끈다. 번체중국어로 페이지를 연다.

### 8.1. 검토했다가 문제가 아니라고 확인한 항목

#### 한국어 글자가 두 폰트로 섞이지 않는다 (종결. 조치 없음)

**처음 제기한 걱정**

첫 스펙에서 다음을 미결(`NEEDS_MAIN_APPROVAL-F`)로 올렸다.

> `Noto Sans TC`가 폰트 스택의 CJK 1순위라서, 한국어 문구의 일부 글자를
> 가져가 버린다. `괴이탐사국`이 한 단어 안에서 두 글꼴로 섞인다.

근거는 Google Fonts CSS의 `unicode-range` 선언이었다. 105개 조각의 선언을
파싱했더니 한글 코드포인트가 들어 있었다. 이 페이지의 한국어 문구 220자 중
19자가 그 안에 걸렸다.

**이 근거는 틀렸다**

`unicode-range`는 **"이 코드포인트는 이 조각에서 찾아라"는 지시일 뿐이다.**
조각 안에 그 글자의 글리프가 실제로 들어 있다는 보장이 아니다.
글리프가 없으면 브라우저는 그 글자만 스택의 다음 폰트로 넘긴다.
즉 선언 범위를 파싱하는 방법으로는 이 질문에 답할 수 없다.

**실제 브라우저로 다시 확인한 결과 (2026-09-12)**

공개 페이지 https://davi-dev.uk/ 에서 확인했다. 절차는 이렇다.

1. `Noto Sans TC:wght@400` 스타일시트를 주입한다.
2. `document.fonts.load()`로 대상 글자의 조각을 강제로 받는다.
3. `document.fonts.ready`를 기다린다.
4. canvas `measureText`로 두 폭을 비교한다.
   - `"Noto Sans TC", monospace`로 지정한 폭
   - `monospace`만 지정한 폭
5. 폭이 다르면 `Noto Sans TC`가 그 글자를 그린 것이다.

| 글자 | `"Noto Sans TC", monospace` | `monospace` | TC가 그렸나 | `fonts.check` |
| --- | --- | --- | --- | --- |
| 怪 | 40 | 34.6 | **그렸다** | `true` |
| 異 | 40 | 34.6 | **그렸다** | `true` |
| 이 (U+C774) | 34.6 | 34.6 | 아니다 | `true` |
| 국 (U+AD6D) | 34.6 | 34.6 | 아니다 | `true` |
| 괴 (U+AD34) | 34.6 | 34.6 | 아니다 | `true` |
| 탐 (U+D0D0) | 34.6 | 34.6 | 아니다 | `true` |
| 사 (U+C0AC) | 34.6 | 34.6 | 아니다 | `true` |

한자 2자는 폭이 34.6에서 40으로 바뀌었다. `Noto Sans TC`가 그렸다는 뜻이다.
한글 5자는 폴백과 폭이 완전히 같다. `Noto Sans TC`가 그리지 않았다는 뜻이다.

**결론**

- 한글은 지금과 똑같이 방문자 OS 기본 글꼴로 그려진다.
- `괴이탐사국`이 한 단어 안에서 섞이는 일은 일어나지 않는다.
- 두 지시("스택 순서 유지" / "한글은 지금처럼 OS 글꼴")는 충돌하지 않는다.
- **조치하지 않는다.** 줄 53·54·60과 `index.html:73`의 `:lang(ko)` 블록을
  건드리지 않는다. 첫 스펙의 "한국어 전용 스택 3줄 추가" 안은 **폐기한다.**

**남긴 교훈 2가지**

1. `document.fonts.check`는 일곱 자 모두에 `true`를 줬다. 이 함수로는
   글리프 존재를 알 수 없다. QA-LAND-007-1에 주의사항으로 남겼다.
2. 글리프가 없어도 `unicode-range`는 걸려 있다. 브라우저가 조각을 먼저
   받아 볼 가능성이 남는다. QA-LAND-007-5에서 실측하기로 했다.
