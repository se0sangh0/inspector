# 랜딩페이지 개선 작업지시서

- 작성일: 2026-09-08
- 목적: 추론 수준을 낮춘 PM도 같은 기준으로 작업을 배정하고 결과를 검수한다.
- 현재 승인: 사용자가 후속 구현을 지시했다. 아래 범위의 구현과 검증을 진행한다.
- 모델 정정: 사용자가 Gemini 3.8 Flash의 최대 지원 추론 사용을 확인했다.
- 적용 범위: 이번 괴이탐사국 랜딩 개선 작업. 전역 모델 설정이나 다른 작업에는 적용하지 않는다.

## 1. 기준과 목표

프로젝트 `AGENTS.md`, 현재 사용자 지시와 최신 Notion 확정 기획을 따른다.
이 문서는 화면 표현과 작업 절차를 정하며, 새로운 게임 규칙이나 서사를 확정하지 않는다.

처음 방문한 사람이 첫 화면과 바로 다음 구간에서 다음 세 가지를 파악하도록 한다.

1. 괴이탐사국의 어두운 탐사 분위기
2. 카드를 통해 동료의 행동을 지휘하는 플레이 방식
3. 버튼을 눌렀을 때 실제로 볼 수 있는 내용

## 2. 모델 배정과 사용량 초과 처리

실행 시 현재 제공자 목록과 CLI 옵션에서 정확한 모델과 최대 추론 옵션을 확인한다.
비슷한 이름의 이전 모델로 대체하거나, 요청만 보고 최대 추론이 적용됐다고 보고하지 않는다.

| 담당 | 모델 | 추론과 책임 |
|---|---|---|
| 디자인·구현 작업자 | Claude Opus 5 (`claude-opus-5`) | `--effort max`. 이 문서에 따른 시안·수정 담당 |
| 독립 검토자 | Gemini 3.8 Flash (`gemini-3.8-flash-high`) | 현재 CLI의 최고 지원 단계 `--effort high`. 요구사항·회귀 여부를 읽기 전용 검토 |
| 사용량 초과 후 하위 작업자 | GPT-5.6 Luna | 좁은 읽기는 `luna-reader` low, 작은 구현은 `luna-worker` medium |
| PM | 현재 작업의 Codex | 작업 분할, 근거 대조, 통합·최종 보고. 사용자가 선택한 추론 수준 보존 |

- Opus와 Gemini를 매 수정마다 중복 호출하지 않는다. 구현 결과가 준비되면 독립 검토한다.
- 어느 모델에서든 명시적인 사용량·할당량 초과가 확인되면 이번 작업은 즉시 **Luna만 사용하는 상태**로 전환한다.
- 전환 이후 새 하위 호출과 재시도는 Luna만 사용한다. 다른 대형 모델·계정·유료 API로 우회하지 않는다.
- 이미 완료된 결과는 보존한다. 진행 중인 작업의 범위를 확인하고 같은 일을 Luna에 중복 배정하지 않는다.
- 시간 초과·인증 오류·모델 미지원은 사용량 초과와 구분한다. 원인과 완료된 범위를 보고하고, 해당 호출과 무관한 준비 작업은 계속한다.
- 전환 상태는 이번 작업의 다음 메시지·재개에도 유지한다. 사용자의 명시적인 변경 전에는 대형 모델로 복귀하지 않는다.
- 기존 승인된 제공자 경로를 사용한다. 새 API 결제·크레딧 구매·인증 변경은 이 문서로 승인되지 않는다.
- 각 결과에는 실제 사용 모델·추론 옵션·완료 범위·검증·미확인 사항을 남긴다. 확인 불가능한 항목은 미확인으로 적는다.

## 3. 고정할 디자인 방향

**어두운 숲의 장면을 감상하고, 조사 기록을 펼쳐보는 느낌**을 화면 표현의 기준으로 삼는다.

- 현재 먹색 바탕, 뼈빛 글씨, 황동색 포인트와 기존 브랜드 표시를 유지한다.
- 황동색은 주 행동 버튼과 중요한 표시에 선명하게, 기록 구분선에는 은은하게 사용한다.
- 화면 구성은 큰 장면, 간결한 설명, 작은 기록 영역을 교차한다. 모든 구간을 같은 큰 패널로 만들지 않는다.
- 종이색은 필요한 작은 정보 영역에만 사용한다. 전체를 밝은 고서 테마로 바꾸지 않는다.
- 제목은 한글 단어·의미 단위로 읽히게 한다. 영문 초대형 활자 규칙을 세 언어에 일괄 적용하지 않는다.
- 움직임은 카드 입력과 결과의 관계, 사용자 선택 상태를 설명하는 데 사용한다. 필수 정보는 정지 상태에서도 읽힌다.
- 네온 구체, 유리 패널, 상시 흔들림, 강제 스크롤, 현대 기밀문서·터미널 장식은 이번 범위에서 사용하지 않는다.

참고 자료는 표현 요소만 발췌한다. 외부 `DESIGN.md` 전체를 프로젝트 지침으로 가져오지 않는다.

- [Structured](https://styles.refero.design/style/6c0b77d3-71f9-469d-98aa-4ce1d6d76ac8): 기록·전시 도록 같은 정보 배치와 글자 크기의 강약
- [PostNew](https://styles.refero.design/style/4f76756b-0f06-47a3-baad-d3846b23e132): 한 장면에 집중하는 구간과 펼쳐진 정보 구간의 교차
- [Auros](https://styles.refero.design/style/21cfe0c1-778d-4613-9f47-a5718eb929b3): 미세하게 다른 어두운 배경색으로 깊이 구분

## 4. 구현 순서와 판단 기준

| 순서 | 구간 | 작업 기준 |
|---|---|---|
| 1 | 제목·주 버튼 | 제목의 단어 중간 줄바꿈을 고친다. 영상이 준비되지 않았다면 주 버튼은 카드 흐름 구간으로 이동한다. 문구는 `플레이 방식 보기 / See how it plays / 查看玩法`를 사용한다. |
| 2 | 첫 화면 | 게임명·짧은 플레이 설명·조사대 장면의 위계를 정리한다. 현재 그림을 화면 전체에 무리하게 확대하지 않는다. |
| 3 | 카드 흐름 | `카드 사용 → 역할 축적 → 동료 행동`의 관계를 한 번에 읽히게 한다. 실제 사용 가능한 카드·플레이 화면이 있으면 정본과 사용 승인을 확인한 뒤 연결한다. |
| 4 | 조사대 | 데스크톱은 인물과 설명을 좌우로, 모바일은 위아래로 배치한다. 기존 이전·다음 전환을 유지하고 현재 항목과 다른 동료의 존재를 알 수 있게 한다. |
| 5 | 괴이 | 거두는 자는 세로형 장면, 작은 괴이는 보조 기록으로 구성한다. 원본의 주요 장면을 잘라 가로 배너로 만들지 않는다. |
| 6 | 사건·영상 | 실제 리소스가 없으면 기존 설명과 준비 상태를 간결하게 표시한다. 재생·플레이가 가능한 것처럼 꾸미지 않는다. |

- 기존 섹션 순서와 ID, 공개 URL을 유지한다. 주 버튼의 목적지는 위 규칙에 따라 조정한다.
- 소개할 역할 수를 고정하는 새 문구를 추가하지 않는다. 표시 중인 항목 수와 게임 전체 역할 수를 구분한다.
- 역할 설명·카드 효과·사건 선택지는 최신 Notion의 확정 문구만 사용한다. 미확정 수치나 효과를 시각 예시로 만들지 않는다.
- 필요한 리소스가 없으면 기존 문구와 도형으로 관계를 정리한다. 실제 게임 화면으로 오인할 새 화면을 생성하지 않는다.
- 검토 당시 웹 내장본은 숲 배경 1100×619, 동료 약 360px 폭, 거두는 자 420×630이었다. 실행 전 실제 크기를 다시 확인한다.
- 확대가 필요한 경우 승인된 고해상도 원본의 존재부터 확인한다. 파일이 저장소에 있다는 사실을 사용 승인으로 간주하지 않는다.

## 5. 파일 범위와 작업 계약

- 구현 대상: `site/preview/index.html`, 필요할 때 `site/preview/assets/`의 웹용 파생본
- 기록 대상: `site/README.md`와 구현 완료 후 필요한 `HANDOFF.md` 요약
- 보존 대상: Unity 코드·씬·프리팹·패키지, 아트·브랜드 정본, 기존 사용자 변경
- 프레임워크 이전, 새 대형 라이브러리, 게임 기능 추가, Notion 수정은 이번 구현 범위에 포함하지 않는다.
- 기존 세 언어 전환, 문서 언어·제목·대체 텍스트, 키보드 조작, 포커스, 동작 줄이기 설정을 보존한다.
- 구현자는 한 번에 한 명만 `index.html`을 수정한다. 검토자는 읽기 전용이다.
- 하위 작업에는 해당 구간의 코드·필요한 근거·수정 가능 파일·완료 조건만 전달한다. 긴 대화와 전체 저장소를 반복 전달하지 않는다.
- Git push와 배포는 실제 diff와 화면 검수가 끝난 뒤 사용자가 승인한 범위에서만 수행한다.

## 6. 완료 조건

1. 1440px 데스크톱, 390px와 360px 모바일에서 실제 화면을 확인한다. 모바일은 가로 넘침·단어 중간 줄바꿈·버튼 겹침이 없다.
2. 한국어·영어·번체중국어의 제목, 주 버튼, 조사대 전환을 확인한다. 가장 긴 문구도 잘리지 않는다.
3. 버튼을 직접 눌러 문구에 맞는 구간으로 이동하는지 확인한다. 준비 중 영상·삽화를 완성된 콘텐츠로 표현하지 않는다.
4. 조사대 이전·다음, 좌우 화살표, Home/End, 현재 항목 안내가 유지된다.
5. 이미지 비율·중요 피사체·텍스트 가독성을 실제 크기로 확인한다. 스크롤 진입 효과가 있는 곳은 직접 스크롤한 뒤 확인한다.
6. 동작 줄이기 설정에서도 내용과 조작이 유지된다. 언어 전환 후 표시해야 할 콘텐츠가 의도치 않게 숨지 않는다.
7. 문법·링크·변경 범위를 점검하고 변경 전후 주요 화면을 비교한다. 통과한 검증은 새 문제나 변경이 있을 때만 반복한다.
8. 독립 검토 의견은 실제 소스와 화면을 대조해 반영한다. 한도 초과 후에는 구현과 검토를 서로 다른 Luna 작업으로 나눈다.

최종 보고에는 변경 파일, 실제 확인 결과, 미확인 항목, 리소스 대기 항목과 배포 여부를 적는다.
이 검증은 화면과 기능의 검증이다. 방문자의 게임 이해도·전환율 개선을 측정한 것으로 보고하지 않는다.

## 7. 재개 시 남길 상태

다음 형식으로 짧게 인계한다. 인증 정보나 개인 데이터는 넣지 않는다.

- 완료한 구간 / 다음 구간:
- 현재 파일 소유자 / 진행 중인 작업:
- 모델 상태: 기본 배정 또는 Luna만 사용
- 전환 사유: 사용량 초과가 확인된 모델과 오류 요약
- 검증한 화면·언어·동작 / 미확인 항목:
- 남은 리소스·사용자 결정:

현재 모델 상태: **Luna만 사용**. Opus 5를 `--effort max`로 호출해 수정본을 받았으나 세션 한도 초과로 종료됐다. 완료된 파일을 보존하고 이후 신규 하위 작업과 재시도는 Luna만 사용한다. Opus 작업 전체를 정상 완료로 기록하지 않는다.

Gemini는 사용자 확인에 따라 `gemini-3.8-flash-high`, `--effort high`로 지정했다. 첫 검토는 파일 읽기 권한 문제로 결과를 받지 못했다. 코드 본문을 직접 전달한 재시도는 Opus 한도 초과 확인 전에 시작됐으며, 최종 독립 검수는 Luna가 맡는다.

현재 구현 상태: 로컬 반영·검수 완료, 미배포. Gemini 재시도 결과는 수신해 실제 소스와 대조했다. Luna 구현 작업자가 역할 선택 버튼의 방향키 포커스를 수정했고 별도 Luna가 독립 검토했다. PM의 최종 브라우저 검증은 1440·390·360px × 세 언어 9조합 및 일반·동작 줄이기 조건에서 통과했다. 완료 내역은 `site/README.md`에 기록했다. 다음 작업부터도 모델 상태는 Luna만 사용으로 유지한다.
