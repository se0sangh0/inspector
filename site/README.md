# INSPECTOR 웹사이트

랜딩 페이지와 GitHub Pages 배포 파일은 이 저장소 안의 `site/`에서 관리합니다.
별도 웹 저장소를 만들지 않습니다.

- `preview/`: GitHub Pages에 공개하는 개발 시안
- `preview/assets/`: 기존 웹 이미지 6종과 공유용 합성 이미지
- `preview/assets/animations/`: 8프레임 애니메이션의 웹용 시트 12종과 첫 프레임 12종
- `animation-assets.json`: 웹용 파생본의 원본 경로·해시·크기 기록
- 공개 주소: [https://davi-dev.uk/](https://davi-dev.uk/)
- 배포 방식: GitHub Actions가 `preview/`를 GitHub Pages 아티팩트로 배포
- 워크플로: [`.github/workflows/deploy-pages.yml`](../.github/workflows/deploy-pages.yml)
- 개선 작업 기준: [랜딩페이지 개선 작업지시서](01_랜딩페이지_개선_작업지시서.md) · 디자인·모델 배정·검수·사용량 초과 후 Luna 전환 규칙

현재 [`preview/index.html`](preview/index.html)은 한국어·영어·중국어 번체를
한 페이지에서 바꾸는 공개 개발 시안입니다. 영상과 일부 삽화 자리는
각 언어의 설명용 문구로 남아 있습니다.

브랜드 정본은 `art/brand/`, 그래픽 검토 원본은
`art/production/graphics-remake/`에 유지합니다. 사이트에서는 정본을 직접 수정하지
않고 웹용 파생본을 `site/preview/assets/`에 만듭니다.

`main`의 `site/preview/**` 또는 배포 워크플로가 바뀌면 자동 배포합니다. GitHub Actions의
`Run workflow`로 수동 배포할 수도 있습니다.

현재 페이지는 개발 중 콘셉트 비주얼을 사용하는 공개 시안입니다. 정식 배포본으로
전환하기 전 승인된 리소스, 공유 이미지와 동영상 파일을 다시 확인합니다.

### 확인 결과

- 1440·390·360px × 번체중국어·한국어·영어 9조합에서 가로 넘침, 버튼·푸터 겹침이 없었습니다. 문의 링크는 44×44px 이상이며 키보드 포커스가 보입니다. 가장 밝은 기본 배경색을 기준으로 계산한 링크 명암비도 5.83:1입니다.
- 한글·번체 라벨 자간은 0.12~0.13px, 영어는 기존 1.68~2.6px를 유지합니다. 흐름 번호는 세 언어 모두 2.4px입니다.
- 실제 소스의 언어 함수 16개 사례와 저장 쓰기 실패 검사를 통과했습니다. 별도 임시 계측 사본의 실제 브라우저에서도 지정된 로캘 6개와 저장소 읽기·쓰기 예외를 확인했습니다. 한국어 브라우저에서 선택한 번체중국어는 새로고침과 탭 재개 뒤에도 유지됐습니다.
- Chrome 152의 `3G` 프로필에서 첫 콘텐츠 페인트는 9,244ms였고, 첫 제목·문서 언어·선택기 모두 한국어였습니다. 메뉴에는 `Slow 3G` 대신 `3G`가 있어 해당 프로필을 사용했습니다. 계측 코드는 배포 파일에 넣지 않았습니다.
- DevTools의 Rendered Fonts에서 `查看玩法` 네 글자가 네트워크의 Noto Sans TC, 굵기 500으로 그려짐을 확인했습니다. 폰트 두 도메인을 차단한 360px 화면에서도 세 언어와 조작이 유지됐습니다. 검사 후 차단·속도·캐시 설정을 복원했습니다.
- 동작 줄이기 에뮬레이션에서 reveal 요소 22개가 모두 보였고, 언어 전환과 직접 선택한 애니메이션 재생이 작동했습니다. 동료 4명·적 2종 이미지, 세 언어 재생 라벨, 조사대 Home·방향키와 포커스도 확인했습니다. 최종 인앱 브라우저의 오류 기록은 0건입니다.
- `node --test site/tests/animation-player.test.cjs`는 10개 통과했습니다. 기존 검사 파일과 잘라내는 애니메이션 코드 구간은 바이트 그대로입니다. 번역 키는 세 언어 각각 76개이며 이름 집합도 같습니다. 전체 JS 구문과 변경 공백 검사도 통과했습니다.
- 공유 이미지 입력 5개와 애니메이션 24개는 해시가 그대로입니다. 공유 이미지는 배경·유닛을 확대하거나 자르지 않았고, 지정 좌표·겹침 순서로 합성했습니다. 파비콘은 밝고 어두운 배경에서 16·32px로 확인했습니다.

### 성능과 스펙에서 보완한 부분

- Lighthouse 13.4.1 모바일 검사에서 변경 전 CLS는 0이었습니다. 첫 수정본은 언어 선택창 너비 변화로 0.001이 나와 선택창 폭을 112px로 고정했습니다. 재검사 CLS는 0입니다. 이 한 줄은 폰트 교체 시 레이아웃 이동을 막기 위한 보완입니다.
- 같은 검사의 변경 전 FCP/LCP는 3.0/3.3초, 최종 수정본은 8.1/8.7초였습니다. 최종 접근성 점수는 100입니다. 사용자 Chrome의 확장 프로그램·네트워크·기기 부하가 포함된 단일 실행값이며, 반복 측정한 성능 보장은 아닙니다. 큰 CDN 스타일시트와 폰트의 로딩 지연은 남아 있습니다. 자체 호스팅·글자 조각 생성·요청 굵기 축소는 승인 범위 밖이라 적용하지 않았습니다.
- 실행 지시서의 키 개수 75개는 문의 키 추가분을 빠뜨린 값입니다. 본문 스펙의 `83 - 8 + 1 = 76`을 따랐습니다. 삭제 자산의 본문 합계 126,999 B도 실제 파일 합계 127,000 B로 기록했습니다.
- Codex 앱 세션에서 직접 구현·검수했고 별도의 `codex exec`는 실행하지 않았습니다. 따라서 CLI 경로·버전·종료 코드를 구현 성공 근거로 쓰지 않았습니다. OG 합성과 HTML 독립 검토는 네이티브 GPT-5.6 Luna 작업자가 맡았습니다. 셸 검사의 정상 종료와 실제 diff를 대조했습니다.
